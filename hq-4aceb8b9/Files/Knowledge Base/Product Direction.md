# Product Direction

Working thinking on how Helthy should look and feel. None of this is final. It is a starting point we refine together.

## The shape of the app

The home page currently reads as one long scroll feed, which feels messy. We want a cleaner, more bifurcated layout.

- **Bottom navigation, four equal destinations:** Home, Scan, List, About.
- **Top right corner:** product search and cart, treated as small utilities rather than main destinations.
- **Product search** is a premium feature, the lighter path for someone who would rather not scan a barcode.
- **Cart** is a simple product list. No checkout, and it does not sync with the other list types.

## The scan moment

The camera should close the instant a barcode is recognized, so the user is never left dismissing it by hand. The flow should feel like the app is keeping up with them.

## A lighter product page

The current product detail view is too prominent and explains itself too much. Copy like "Why this recommendation" and "OK choice" reads as the app justifying itself. The cleaner posture is to show the verdict plainly and trust the user to ask for more if they want it.

## Design north stars

- Warm, benefit-forward onboarding that gets someone past the learning curve quickly.
- Show visualizations, not raw numbers. The health score and trends lead; the hard figures sit one tap away.
- The only surprises should be good surprises.

## Products we study

- **Yuka** is the north star for barcode-led product scoring. We learn from what works for it, and we pay close attention to where its model breaks down for a diabetes-first audience.
- **WeightWatchers** for habit and program design.
- **Google Health** (the app for Fitbit) for how it presents personal health data.
- **Cal AI** for image-recognition done well.
